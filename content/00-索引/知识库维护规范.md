# 知识库维护规范

## 基本原则

1. 先建入口，再移动文件。
2. 标准化笔记作为日常使用入口，已整理完成的原始资料可以删除。
3. 实战复盘优先于泛教程。
4. 标签少而精，每篇 1-3 个核心标签即可。
5. 临时内容先归档到 `90-收集箱/待确认`，确认无用后再删除。

## 新增故障复盘

使用 [[排障复盘模板]]，并挂到对应索引。

必填结构：

- 现象
- 环境
- 排查过程
- 根因
- 解决方法
- 验证结果
- 预防措施
- 相关笔记

推荐位置：

| 类型 | 目录 |
|---|---|
| Linux 故障 | `08-故障复盘` |
| Kubernetes 故障 | `08-故障复盘` |
| Docker/containerd 故障 | `08-故障复盘` |

## 新增自动化手册

使用 [[Shell脚本说明模板]] 或 [[部署手册模板]]。

必填结构：

- 目标
- 适用场景
- 参数配置
- 核心逻辑
- 部署方式
- 验证方法
- 风险与回滚
- 相关笔记

推荐位置：

| 类型 | 目录 |
|---|---|
| Shell 自动化 | `09-自动化与部署` |
| Docker 部署 | `09-自动化与部署` |
| 服务部署 | `09-自动化与部署` |

## 新增命令速查

使用 [[命令速查模板]]。

推荐位置：`07-命令速查`

适合内容：

- 高频命令组合。
- 容易记错的参数。
- 有风险的删除、清理、变更命令。
- 排障时需要反复查的命令。

## 技术栈索引规则

`00-索引` 只放入口级索引，避免每个技术都新建索引导致目录膨胀。

新增技术内容时，先放入 [[技术栈索引]]。满足任意一个条件，再独立建专题索引：

- 该技术已有 5 篇以上笔记。
- 经常用于排障或部署。
- 内容横跨部署、命令、配置、故障等多个栏目。
- 已经需要分栏目管理。

个人兴趣、游戏配置、生活资料不放入 [[技术栈索引]]。

## 收集箱规则

1. 空文件、失败剪藏、默认欢迎页先放入 `90-收集箱/待确认`。
2. 附件不确定是否引用时，先放入 `90-收集箱/待确认附件`。
3. 保留观察后再删除。
4. 如果发现有价值，再恢复并挂到索引。
